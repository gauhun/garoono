<p>I&#39;m a solo dev with about 16 Flutter apps live on iOS and Android<br>This year two of them, PushPass and GetUp, ran into three different App Store blockers<br>No crashes, no bugs Flutter could have caught<br>Just policy, metadata and one entitlement Xcode never complained about</p>

<h2>The 30 second version</h2>
<p>If your app sends user data to any AI model, answer &quot;who, what, where&quot; in App Review Notes and ask for consent in the app before the first upload</p>
<p>If you sell auto-renewable subscriptions, every App Store description in every locale ends with a Terms of Use (EULA) link</p>
<p>If you use Screen Time APIs, request the Family Controls Distribution entitlement for the app and every extension on the day you add the feature</p>

<h2>Blocker 1: Information Needed on an AI feature</h2>
<p>GetUp 1.1.2, October 2026<br>Not a hard rejection, a Guideline 2.1 &quot;Information Needed&quot; message</p>
<p>Apple asked three things:</p>
<ul>
<li>Who hosts the AI model?</li>
<li>Is it third-party AI?</li>
<li>Does user data go to it?</li>
</ul>
<p>It lines up with a rule Apple changed on November 13, 2025 (<a href="https://developer.apple.com/news/?id=ey6d8onl" target="_blank" rel="noopener noreferrer">Apple</a>)<br>Guideline 5.1.2(i) now says you must disclose where personal data is shared with third parties, &quot;including with third-party AI, and obtain explicit permission before doing so&quot; (<a href="https://developer.apple.com/app-store/review/guidelines/#data-use-and-sharing" target="_blank" rel="noopener noreferrer">App Review Guidelines</a>)</p>
<p>That sentence has two jobs in it<br>Disclosure, and permission</p>
<p>Here&#39;s what I now put in App Review Notes for any app that touches a model, before Apple has to ask:</p>
<ul>
<li>Which parts run on device and which run in the cloud</li>
<li>The provider&#39;s name, for example Google&#39;s Gemini through Firebase AI Logic</li>
<li>Exactly what data is sent, field by field</li>
<li>How long the provider keeps it and whether it&#39;s used for training</li>
<li>Where the consent screen is and how a reviewer reaches it</li>
</ul>
<p>Then the in-app part<br>The AI provider goes into the third-party list in your privacy policy, by name<br>And the user agrees before the first upload, on a screen that says what goes where</p>
<blockquote>
<p>A Settings toggle that&#39;s on by default is not consent</p>
</blockquote>
<p>One more lesson from that review<br>When you reply to an Information Needed message, describe the build Apple actually reviewed, not the one on your laptop<br>If that build has no consent screen, don&#39;t promise one in your reply<br>Remove it from review, ship the fixed build, and put the answer in its Review Notes</p>
<p>Here&#39;s a minimal consent gate with <code>flutter_bloc</code>, default is false, always</p>
<pre><code class="language-dart">class AiConsentCubit extends Cubit&lt;bool&gt; {
  AiConsentCubit(this._prefs) : super(_prefs.getBool(_key) ?? false);
  static const _key = &#39;ai_consent_v1&#39;;
  final SharedPreferences _prefs;

  Future&lt;void&gt; grant() async {
    await _prefs.setBool(_key, true);
    emit(true);
  }
}

Future&lt;void&gt; analyzePhoto(BuildContext context, Uint8List photo) async {
  final consent = context.read&lt;AiConsentCubit&gt;();
  final ai = context.read&lt;AiRepository&gt;();
  if (!consent.state) {
    final agreed = await showAiConsentSheet(context);
    if (agreed != true) return;
    await consent.grant();
  }
  await ai.analyze(photo);
}
</code></pre>
<p>Every call to the model goes through that one function<br>If someone adds a second path that skips it, code review catches it because it&#39;s the only place <code>AiRepository</code> gets called</p>
<h2>Blocker 2: The EULA link nobody puts in the description</h2>
<p>This one is boring and it still blocked a submission</p>
<p>If your app has auto-renewable subscriptions, Apple says your app and your App Store metadata must include links to your Terms of Use and Privacy Policy (<a href="https://developer.apple.com/app-store/subscriptions/" target="_blank" rel="noopener noreferrer">Apple</a>)</p>
<p>Privacy has its own field in App Store Connect<br>Terms of Use, if you use Apple&#39;s standard EULA, doesn&#39;t<br>So it goes at the end of the App Store description</p>
<p>Miss it and automated review blocks the submission before a human ever looks</p>
<p>The trap is the words &quot;every locale&quot;<br>Localize into eight languages and you have eight descriptions<br>Someone rewrites the German one for a keyword push and drops the footer, and that&#39;s enough</p>
<p>So don&#39;t paste it by hand<br>Bake the link into your listing source, and let a tiny script check every locale before upload<br>If you keep metadata in fastlane, it&#39;s this:</p>
<pre><code class="language-dart">import &#39;dart:io&#39;;

const eula =
    &#39;https://www.apple.com/legal/internet-services/itunes/dev/stdeula/&#39;;

void main() {
  final missing = Directory(&#39;fastlane/metadata&#39;)
      .listSync()
      .whereType&lt;Directory&gt;()
      .map((d) =&gt; File(&#39;${d.path}/description.txt&#39;))
      .where((f) =&gt; f.existsSync() &amp;&amp; !f.readAsStringSync().contains(eula))
      .map((f) =&gt; f.parent.path)
      .toList();
  if (missing.isNotEmpty) {
    stderr.writeln(&#39;EULA link missing in: ${missing.join(&#39;, &#39;)}&#39;);
    exit(1);
  }
  stdout.writeln(&#39;EULA link found in every locale&#39;);
}
</code></pre>
<p>That&#39;s the standard Apple EULA URL<br>If you wrote your own terms, check for your URL instead</p>
<p>And don&#39;t forget the paywall<br>The same Apple page lists what the sign-up screen itself must show: the subscription name and length, the full renewal price, and a way to restore purchases (<a href="https://developer.apple.com/app-store/subscriptions/" target="_blank" rel="noopener noreferrer">Apple</a>)<br>Put the two links there too</p>
<h2>Blocker 3: Family Controls, the entitlement that sails through TestFlight</h2>
<p>This is the nasty one, it hit both PushPass and GetUp</p>
<p>If your app uses Screen Time APIs (FamilyControls, ManagedSettings, DeviceActivity, shield extensions), you need the Family Controls entitlement<br>There&#39;s a Development version and a Distribution version</p>
<p>The Development capability builds, it signs, it uploads, and TestFlight is happy<br>Then App Review blocks it</p>
<p>Apple&#39;s Family Controls setup guide covers the part people miss: the Screen Time extensions, like Device Activity Monitor, Device Activity Report, Shield Action and Shield Configuration, need the capability on their own App IDs too (<a href="https://developer.apple.com/documentation/xcode/configuring-family-controls" target="_blank" rel="noopener noreferrer">Apple</a>)<br>A blocker app can easily have four bundle IDs, which can mean four requests through the <a href="https://developer.apple.com/contact/request/family-controls-distribution" target="_blank" rel="noopener noreferrer">distribution request form</a></p>
<p>Flutter makes this easy to miss<br>Those extensions live in the <code>ios</code> folder as native targets<br><code>flutter build ipa</code> builds them, signs them, and never says a word about distribution</p>
<p>And approvals are not fast<br>Developers on Apple&#39;s forums report requests sitting in &quot;Submitted&quot; for weeks (<a href="https://developer.apple.com/forums/thread/824193" target="_blank" rel="noopener noreferrer">Apple Developer Forums</a>)</p>
<p>One update worth knowing<br>In a 2026 forum reply, Apple said approval can now be scoped to the whole team instead of each bundle ID (<a href="https://developer.apple.com/forums/thread/828085" target="_blank" rel="noopener noreferrer">Apple Developer Forums</a>)<br>That wasn&#39;t how mine went, so don&#39;t assume either way<br>Open Certificates, Identifiers &amp; Profiles and check that every single identifier shows Family Controls as assigned for distribution</p>
<p>My rule now: request it the same day the Screen Time feature gets added, not the day before submitting</p>

<h2>Quick answers</h2>
<h3>Does on-device AI count as third-party AI?</h3>
<p>The rule is about sharing personal data with third parties<br>Data that never leaves the phone isn&#39;t shared<br>But say in Review Notes which parts run on device and which don&#39;t, it answers the question before it&#39;s asked</p>
<h3>Can I just use Apple&#39;s standard EULA?</h3>
<p>Yes, link the standard EULA URL in the description<br>If you wrote custom terms, you can add them in App Store Connect instead</p>
<h3>Is Family Controls approval per app or per team?</h3>
<p>Apple&#39;s setup guide puts the capability on each extension, and a newer forum reply talks about team-wide approval<br>Check the portal for every identifier before you submit</p>
<h3>Will TestFlight catch any of this?</h3>
<p>No<br>TestFlight tests your binary<br>These were about metadata, consent and entitlements, and the Family Controls build installs and runs fine from TestFlight</p>
<h2>My takeaway</h2>
<p>None of these were hard<br>Each one was a single line, a single link or a single form</p>
<p>What made them expensive was finding out at review time<br>So the checklist runs before the upload, every time, for every app</p>
